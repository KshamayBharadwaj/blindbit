BlindBit Help & Guide

BlindBit is a zero-knowledge file vault — your files are encrypted in your browser before they ever reach the server. The server only stores scrambled data it cannot read.

Privacy by Design BlindBit never sees your files, filenames, or keys. Everything is encrypted and decrypted locally in your browser using the Web Crypto API.

01 Quick Start

1

Create Your Account

Click Sign Up and create a passkey (or set a passphrase if your browser doesn't support PRF). Save your recovery phrase — this is your only backup.

2

Upload a File

Click Upload in the sidebar, select any file, and click Lock & Upload. The file is encrypted in your browser before it leaves your machine.

3

Open a File

Click Open on any file in your vault. The encrypted data is fetched, decrypted in your browser, and your browser downloads the original file.

4

Share a File

Go to a file's details page, click Share, enter the recipient's username, and send. They'll see the file under Shared With You on their dashboard.

02 Authentication

BlindBit uses passkeys (WebAuthn) instead of passwords. You sign in with your device's built-in biometrics or PIN.

Signing Up

  1. Enter your username, email, and display name
  2. Your browser will prompt you to create a passkey (Face ID, Touch ID, Windows Hello, or a security key)
  3. Choose whether to set a passphrase (recommended for Firefox users or as a backup)
  4. Save your 24-word recovery phrase — this is your only way to recover access if you lose all devices

Signing In

  1. Enter your username
  2. Your browser prompts you to authenticate with your passkey
  3. If you set a passphrase, you'll be prompted to enter it after the passkey check
  4. You're in — your vault decrypts locally using the keys derived from your passkey
Browser Compatibility Chrome and Edge support the PRF extension (your passkey directly derives your encryption key). Firefox and Safari do not — you'll use the passphrase fallback instead. Both paths are fully supported.

Passphrase

A passphrase is an optional extra layer. If you enable it:

  • Registration: You set a passphrase (min 12 characters) after creating your passkey
  • Login: You authenticate with your passkey first, then enter your passphrase
  • The passphrase unlocks your Master Key (wrapped under an Argon2id-derived key)

03 Your Vault

The My Vault page is your dashboard. It shows your files, files shared with you, and your vault status.

Dashboard Cards

  • Your Files — Total number of files you've uploaded
  • Shared With You — Number of files others have shared with you
  • Status — Shows "Secure" when everything is working

Uploading a File

  1. Click Upload in the sidebar
  2. Drag and drop files, or click to browse (up to 500MB per file — larger files are split into encrypted chunks)
  3. Click Lock & Upload
  4. The file is encrypted with AES-256-GCM in your browser, then sent to the server
  5. You're redirected back to your vault when complete
Filename Privacy Even filenames are encrypted. On the server and in the database, your file is stored with a scrambled name.

Opening a File

  1. Click Open on any file in your vault
  2. The encrypted data is fetched from the server
  3. Your browser decrypts the file locally using the file key
  4. Your browser downloads the decrypted file with its original name
Decryption Requires Your Session You must be logged in to decrypt files. The decryption key is derived from your passkey (or passphrase) during login.

04 Sharing Files

Share files with other BlindBit users without exposing your keys.

How to Share

  1. Go to the file's details page (click the file name in your vault)
  2. Click Share
  3. Enter the recipient's username or email
  4. The file key is wrapped under the recipient's public key (ECDH) in your browser
  5. Hit Share — the recipient can now open the file from their dashboard

Viewing Shared Files

Files shared with you appear in the Shared With You section on your dashboard and in the sidebar's Shared page. Click Open to decrypt and download them (requires the full ECDH key chain — coming soon).

Revoking a Share

  1. Go to the file's details page
  2. Click Revoke next to the recipient's name
  3. Confirm — the file will be re-encrypted with a new key and the recipient loses access
End-to-End Encrypted Sharing The file key is wrapped using ECDH (X25519) between an ephemeral keypair and the recipient's public key. The server only stores the wrapped key and ephemeral public key — it cannot unwrap it.

05 Trusted Devices

Every device you sign in with is automatically added as a trusted device. You can view and manage them from the Devices page in the sidebar.

What You See

  • Device name (e.g. "Chrome on Windows", "Safari on macOS")
  • Device icon — laptop, phone, or tablet detected from the name
  • "Current" badge on the device you're using now
  • Auth method badge: Passkey Only or Passkey + Passphrase
  • When the device was first added and last used

Removing a Device

To remove a trusted device:

  1. Click Remove next to the device
  2. A modal appears asking to send a one-time code to your email
  3. Click Send Code — a 6-digit OTP is emailed to you (expires in 10 minutes)
  4. Enter the code and click Remove Device
  5. The device record is deleted — it will need to re-authenticate next time
OTP Email In development mode, OTP emails are printed to your terminal console. Configure SMTP in settings.py for real email delivery in production.

06 Account Recovery

Your 24-word BIP39 recovery phrase is generated during registration and is the only way to recover your vault if you lose access to all your devices.

BlindBit Cannot Recover Your Phrase The recovery phrase is generated in your browser and is never sent to the server. Save it somewhere safe — if you lose it, your vault is permanently inaccessible.

During Registration

  1. After creating your account, a 24-word recovery phrase is generated
  2. Download or copy the phrase and store it securely (password manager, offline backup, safe)
  3. Check the confirmation box and click Confirm to proceed
  4. You can optionally set a BIP39 passphrase (different from your login passphrase) — this adds extra security but you must remember it

Recovering Your Account

  1. Go to the Recovery page from the sign-in screen
  2. Enter your 24-word phrase and optional BIP39 passphrase
  3. Your Master Key is derived from the phrase and you can create a new passkey

07 Troubleshooting

Need Help? File an issue at github.com/anomalyco/blindbit.

Decryption Fails with "Failed to fetch file data"

The server returned a 404 or error. Make sure the file exists and you have access (either as owner or via a share).

Passkey Creation Fails

Some browsers block WebAuthn on insecure origins (HTTP). Use 127.0.0.1 instead of localhost, or set up HTTPS.

"User not found" During Login

Type the exact username you registered with. Usernames are case-sensitive.

OTP Email Not Received

In development, OTP emails are printed to the terminal where you ran python manage.py runserver. Check that terminal output.

File Upload Gets Stuck

Large files (over ~200MB) take time to encrypt in the browser. Wait for the progress bar to complete; files are encrypted chunk by chunk so the browser stays responsive. If it truly hangs, refresh and try again — already-uploaded chunks are reused.

Passphrase Login Loops or Returns to Login

Try clearing your site data and cookies for BlindBit, then sign in fresh. This resolves most session conflicts.
